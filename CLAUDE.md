# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Web bán mỹ phẩm B2C **T&C Cosmetics** (tên cũ Glow VN, đổi ở P18) nhập từ Việt Nam, bán tại Myanmar. Kế hoạch chi tiết: [PLAN.md](PLAN.md). Triển khai: [DEPLOY.md](DEPLOY.md); runbook tên miền **tandcstore.com** (DNS ở inet.vn) + server `10.201.42.65` (dùng chung với web VCM: Docker Compose project `tandc` sau Nginx/Certbot sẵn có, cổng `127.0.0.1:3000`, **không** Coolify): danh sách lệnh [docs/lenh-trien-khai-tandcstore.md](docs/lenh-trien-khai-tandcstore.md) (đi thẳng lên server, chạy thử ngay trên tandcstore.com với nhận đơn tắt), giải thích + sự cố [docs/huong-dan-trien-khai-tandcstore.md](docs/huong-dan-trien-khai-tandcstore.md).

## Cách làm việc
- Trả lời bằng **tiếng Việt**, ngắn gọn.
- Làm theo phase trong PLAN.md; **dừng chờ duyệt** sau mỗi phase/bước lớn.
- Điểm chưa rõ → hỏi dạng lựa chọn, có đề xuất khuyến nghị. Thông tin về dịch vụ/luật/thư viện Myanmar chưa kiểm chứng → ghi **[CẦN XÁC MINH]**, không tự giả định.
- Đổi stack/kiến trúc chỉ khi có lý do rõ ràng và được duyệt.

## Stack
Next.js App Router (TS, `output: "standalone"`) · Tailwind + shadcn/ui · PostgreSQL + Prisma · Better Auth + RBAC tự viết · next-intl · PWA · Vitest · Playwright · npm · Node 24 LTS (ghim trong `.nvmrc`, Dockerfile).
Next.js 16 có API mới (proxy thay middleware, Cache Components bật) → đọc `node_modules/next/dist/docs/` trước khi viết code Next (xem AGENTS.md).

## Quy tắc bắt buộc
**Portability (Vercel/Neon ↔ server riêng chạy Docker Compose, cùng một code)**
- Chỉ dùng PostgreSQL chuẩn qua Prisma; không dùng tính năng riêng của nhà cung cấp.
- Không dùng tính năng chỉ có trên Vercel trong logic lõi. Lưu file qua adapter `STORAGE_DRIVER=vercel-blob|local`.
- Tác vụ định kỳ = route `GET/POST /api/cron/<job>`, header `Authorization: Bearer <CRON_SECRET>` (Vercel Cron gửi sẵn).
- Mọi URL/cấu hình lấy từ env (validate bằng Zod ở `src/lib/env.ts`). Thêm biến mới → cập nhật `.env.example` kèm ghi chú theo môi trường. **Không commit secret.**

**Kho (ưu tiên cao nhất)**
- Tồn kho chỉ thay đổi qua `StockDocument` → `StockLedger` (ghi thêm, không sửa/xoá) + cập nhật `StockBalance` trong **cùng transaction**, khoá dòng bằng `SELECT … FOR UPDATE`. Không bao giờ sửa số lượng trực tiếp.
- Xuất hàng theo FEFO; không bán lô có hạn dùng dưới ngưỡng cấu hình (mặc định 90 ngày).
- `Product.requiresExpiry`: mặc định true; `Batch.expiryStatus=DATED` cần ngày, `NONE` không áp dụng hạn và dùng FIFO sau các lô có ngày, `UNKNOWN` chặn bán đến khi xác nhận hạn thật. PAO (`paoMonths`) tách khỏi ngày hết hạn lô. Mọi truy vấn khả dụng phải dùng cùng điều kiện hạn dùng.
- Nhập/cập nhật SP bằng Excel (`catalog/catalog-import.ts`, một sheet, cột ở `lib/catalog-sheet.ts`, file sinh lúc tải ở `catalog-template.ts`/`catalog-workbook.ts`): SKU có sẵn → cập nhật (ô trống giữ nguyên, không đổi kho/combo), không SKU → SP mới ẩn (gộp biến thể theo tên + thương hiệu); có số lượng → phiếu NHẬP NHÁP theo kho bán. Xem trước chỉ đọc; xác nhận chạy lại kiểm tra trong một transaction (khoá chung với `saveProduct`), chốt tỷ giá đã xem, chặn nhập lặp file có tồn (`CatalogOpeningImport`). COD hoàn tất chỉ ghi nhận thu khách; `orders/cod.ts` đối soát tiền về riêng, quyền ADMIN, có số thực nhận/phí/mã tham chiếu và audit.
- Giữ hàng ở cấp biến thể; phân lô và xuất kho khi bàn giao vận chuyển. Combo trừ kho từng thành phần. Tester/quà là `stockType=TESTER`, không bán được.
- Landed cost tính theo lô, lưu tỷ giá VND/MMK tại thời điểm nhập.
- **Hai kho bán (P24):** mỗi SP thuộc đúng một kho bán (`Product.stockLocationId`); nhập/chuyển vào kho bán, tồn bán (`baseAvailability`), xuất đơn (`issueOrderStock`, mỗi kho một phiếu ISSUE) đều theo kho của SP. Combo + thành phần cùng kho. `Location.active=false` = ngừng dùng (không xoá vì ledger). `Location.pricingMode`: `VN_IMPORT` (Kho Thắm — lô giá `unitCostVnd`, giá = VND × tỷ giá × (1+%) + ship MMK/kg × khối lượng) hoặc `LOCAL_MMK` (Kho Chi — lô giá `unitCostMmk`, `landedCostMmk = unitCostMmk` lúc tạo; giá = vốn MMK + `Product.fixedProfitMmk`). Lô có đúng một loại tiền (CHECK ở DB). Quản lý kho: `/admin/settings/warehouses` (`server/inventory/warehouses.ts`).

**Code**
- Logic nghiệp vụ nằm ở `src/server/<domain>/`, không import Next/Vercel → test được bằng Vitest.
- Mọi Server Action/route handler: validate input (Zod) + kiểm tra quyền phía server (`requirePermission` trong `src/server/auth/session.ts`, bảng quyền ở `roles.ts`). Middleware không phải lớp bảo mật.
- Chuyển trạng thái đơn chỉ qua `src/server/orders/state-machine.ts`.
- Tiền là số nguyên (MMK, VND); tỷ giá là `Decimal`. Thời gian lưu UTC; hiển thị theo Asia/Yangon hoặc Asia/Ho_Chi_Minh.
- Không viết cứng chuỗi giao diện: storefront `messages/store.{my,en,vi}.json` (mặc định `my`; unit test `messages-parity` ép cùng bộ key); admin `messages/admin.{vi,en,my}.json`.
- Chữ Myanmar dùng Unicode. Input tìm kiếm/form đi qua `src/lib/myanmar` (phát hiện + chuyển Zawgyi → Unicode).
- Storefront: ưu tiên Server Components, JS client tối thiểu, `next/image` (AVIF/WebP, lazy). Phải dùng được trên Slow 3G.
- Admin: URL `/admin/...`, locale lấy từ cookie `ADMIN_LOCALE`; storefront: `/` (my), `/en`, `/vi` (P22). Tiền tố URL theo locale: `localePrefix`/`localizedPath` (`src/lib/site.ts`), không viết cứng `"/en"`.
- CSP (P21, `src/lib/csp.ts`): storefront + file công khai đặt trong `next.config.ts` (`script-src 'unsafe-inline'` — static shell không gắn nonce được); admin + cổng CTV đặt trong `proxy.ts` với nonce mỗi request + `'strict-dynamic'`. Thêm script/ảnh/kết nối từ domain ngoài → sửa `buildCsp`, chạy `tests/e2e/csp.spec.ts`.
- Tên thương hiệu hiển thị lấy từ `src/lib/brand.ts` (`BRAND_NAME`, `BRAND_MARK`); messages viết thẳng tên; icon/ảnh OG sinh bằng `scripts/generate-icons.mjs` / `generate-og.mjs`. Tiền tố kỹ thuật `glow` (cookie `glow-customer`/`glow_ref`, header `x-glow-portal`, `phone.glow.invalid`, DB `glow`, repo `glow-mm`, `*@glow.local`, `/opt/glow`) **cố ý giữ** — đổi sẽ đăng xuất khách/mất link CTV.
- Màu dùng design token trong `globals.css` (màu chính `#E8657A`, phụ `#7FB89A`, nền `#FFF8F5`); không hardcode màu trong component.

Thêm/sửa chuỗi `my` → thêm key vào `messages/review-my.json` (danh sách chờ người bản ngữ duyệt); `npm run i18n:export` / `i18n:import -- file.csv` trao đổi qua CSV.
- **Test:** `tests/unit` (logic thuần, `server-only` alias rỗng) · `tests/integration` (DB `glow_test`, chạy tuần tự, fixture ở `fixtures.ts`) · `tests/e2e` (1 worker, build standalone cổng 3100, global setup = migrate + seed + xoá `rateLimit`; project `mobile` Pixel 7 và `desktop` chỉ chạy `*.desktop.spec.ts`; helper `login`, `openAdminNav`). CI `.github/workflows/ci.yml` chạy `npm test` với Postgres 17.

## Kiểm thử & triển khai
- **Thay đổi local:** `npm run check` + test bị ảnh hưởng (`npx vitest run <file>`; integration khi đụng DB/transaction; `npx playwright test <spec> --project=…` chỉ spec liên quan). **Không** tự chạy full E2E sau thay đổi UI nhỏ.
- **Component/layout dùng chung** (`src/components/*`, layout, `globals.css`, `messages/*`, `proxy.ts`, `lib/csp.ts`): grep nơi import → chạy spec của mọi trang bị ảnh hưởng (cả `mobile` và `desktop` nếu có).
- **Full E2E** (`npm test` hoặc job `e2e` của CI: GitHub → Actions → CI → Run workflow trên `dev`; tự chạy khi PR vào `main` và hằng tuần): bắt buộc trước khi merge `main`/phát hành và cho thay đổi rủi ro cao — kho/ledger/FEFO, state-machine/transitions đơn, checkout, auth/RBAC/rate limit, migration Prisma, CSP/proxy, env.
- **Báo cáo test** luôn đủ 4 dòng: Đạt / Lỗi / Bỏ qua / Không chạy (kèm lý do).
- **Triển khai:** không có staging; người dùng tự deploy thủ công lên server từ tag `release-*` rồi chạy smoke. Claude **không** SSH/deploy. Sửa `docker-compose.prod.yml`, `Dockerfile`, `ops/*`, `.github/workflows/*`, cấu hình Nginx → phải được duyệt trước.
- **Tag `release-YYYYMMDD-HHMM`** chỉ gắn lên commit `main` đã có CI full xanh (tag = đã qua kiểm tra bắt buộc); kiểm tra lỗi → không gắn tag, không deploy. Rollback = deploy lại tag trước (quy trình đã diễn tập, xem docs triển khai).
- **Secret:** không in env/secret ra log, script, báo cáo test; test chỉ dùng giá trị `.env.test`.

## Git
- Làm việc trên `dev`; `main` chỉ chứa code đã test. Merge vào `main` khi CI xanh, gồm cả full E2E (mục trên).
- Commit sau mỗi bước hoàn thành.
